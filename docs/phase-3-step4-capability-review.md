# Phase 3 step 4 capability review — stopped before build

The operator authorized step 4 on 9 October 2026 subject to two explicit stop conditions. The first condition is met: the existing Phase 1 OMS and broker order contract cannot express an entry that can fill **only at the next ASX open and at or below the card limit**. No card UI, hand-off layer, fake-broker submission path, or consolidation mutation was built. Steps 5–6 remain unauthorized.

## Entry order incompatibility

`qat.data.broker.adapter.Order` has `order_type` values `market` and `stop` plus an optional `limit_price`; it has no open-auction-only intent or expiry instruction. `OMS.submit_order` creates a pending order through `_new_pending_order`, which generates a new order ID and carries a reference price, stop and target but no entry limit or open-only condition. `OMS.sign_off` calls `broker.place_order` after its checks. The IBKR translation maps a `limit_price` to an ordinary `LimitOrder(..., tif="GTC")` and otherwise uses a GTC market order, including for bracket parents. A GTC limit can remain eligible after the opening auction. Neither is equivalent to the frozen next-open entry rule; attaching the card's limit to the existing field would silently change the strategy's execution semantics.

The existing Phase 1 order ID is also generated by `new_order_id()` rather than supplied from a card identity. Safe card-level idempotency therefore requires an explicit OMS contract change rather than assigning an ID after order creation. The current Phase 1 sizing and order interfaces use binary floats, while the operational candidate carries exact Decimal evidence; a reviewed conversion and comparison policy is needed at this boundary.

**Proposed prerequisite for separate operator review:** extend the Phase 1 candidate, OMS order and broker capability contract with an explicit next-open limit intent, a bound session/open, and the card ID as a durable idempotency key. Refuse unsupported exchanges, accounts and adapters before creating a pending order. Prove with fake adapters that the order is valid only in the specified opening auction, never later in the session, cannot exceed the limit, retains protective-stop semantics, and cannot be retransmitted after a lost acknowledgement. Only after that capability exists should a step 4 UI or hand-off be built. No approximation through ordinary market, GTC limit or a timed cancel is acceptable.

## Exit sign-off gap

The frozen [Phase 2 strategy specification](superpowers/specs/2026-10-01-phase-2-authoritative-swing-strategy-design.md) defines the mechanical position lifecycle: initial protective stop and a banked +1R target, runner breakeven and ATR trailing ratchet after the partial target, daily-close invalidation, and the ten-session time stop. The frozen [Phase 3 integration specification](phase-3-recommend-mode-integration-spec.md) says held positions remain managed under applicable rules, but does not define how each strategy-generated target, stop change, trailing update, invalidation or time-stop exit is presented for human sign-off. It also does not define what happens to existing broker protection while an exit waits, is declined, or expires. The existing Phase 1 OMS has safety logic for protective exits, but applying it to this new strategy without an operator decision would invent step 4 behavior.

**Proposed decision for operator review:** define an exit card and sign-off matrix for each Phase 2 trigger, with a clear protective-order state while approval is pending; how to handle decline, no response, a changed holding or stop, overlapping triggers, and a halt; and whether any protective stop/target maintenance is mandatory safety management rather than a discretionary strategy order. Preserve one exit per share and the Phase 2 trigger priority. Then test each path against fake broker state before any paper rehearsal.

The future IBKR binary-price capture ruling is recorded in [the split-factor source decision](phase-3-split-factor-source-proposal.md). No real IBKR, ASX, Yahoo or other vendor access occurred in this review.
