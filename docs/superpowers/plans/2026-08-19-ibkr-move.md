# Moving to IBKR and the ASX — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Reach a state where this application can trade the ASX through an IBKR paper account with the same protection guarantees it had on Alpaca — nothing silently degraded.

**Spec:** `docs/superpowers/specs/2026-08-12-asx-transferable-validation-design.md`. **Read it first.** This plan implements it and corrects it where 19 August measurement disagrees.

**Trial close:** `docs/2026-08-19-us-trial-close.md` — what the US phase did and did not establish.

## THIS IS FOUR SUB-PROJECTS, NOT ONE

The spec's W1 is a feasibility spike, not an implementation. Implementing it spans four subsystems with different blockers, and forcing them into one plan would produce a plan nobody can execute.

| Stage | What | Blocked on |
|---|---|---|
| **1. The adapter can be trusted** | W1.1 measurement, the three implementable methods, the order-identity bridge | **The IBKR paper account existing.** Nothing else. |
| **2. Market data** | Which vendor supplies ASX daily bars, corporate-action adjusted, point-in-time | A commercial decision |
| **3. ASX trading rules** | Minimum marketable parcel, tick sizes, T+2, session and auction handling | Stage 1 |
| **4. Regime re-sourcing** | AU volatility and curve inputs, or a recorded decision not to | Stage 1 plus the ablation question |

**Only Stage 1 is planned in detail below.** The others get their own spec then plan cycle once Stage 1's measurement says what they actually need. Planning them now would be guessing.

## Global Constraints

- **Everything built is either market-agnostic or cheap to abandon.** The operative rule since 12 August.
- **A defect that corrupts the record is fix-immediately.**
- **PAPER ONLY.** `LivePortInPaperModeError` already refuses a live port (4001/7496) in paper mode — W1.4, landed 12 August. Do not weaken it. The guard is deliberately one-directional: live mode against a paper port is the safe mismatch and is allowed.
- **Read-only first.** `IBAdapter` has a `read_only` mode and `_check_not_read_only`. Every W1.1 measurement runs read-only. **No order is placed on IBKR until the measurement is complete and reported.**
- Any script run outside pytest passes its own `data_dir`; `Settings(_env_file=None).data_dir` is the LIVE directory.
- Formats with `black`, never `ruff format`. Verify with `ruff check .`, `black --check .`, `mypy src`, `bandit -r src -q`, `pytest tests -q`, all via `./.venv/Scripts/python.exe`.
- Baseline: **2,194 passed, 25 skipped** (2,219 collected) at `f537a9e` (M94, deployed).

### The consequence that is easy to miss

`_correct_announced_price` — M70 and M71 — resolves an incoming fill through `_order_the_broker_calls(raw.order_id)`. With no identity bridge that lookup cannot match, so **both corrections go dormant on IBKR without erroring**. The app would record entry and exit prices it never paid, silently, exactly as it did before M70 was written. That is why Task 3 sits in Stage 1 rather than being deferred.

### Task 3: The order-identity bridge, or M70 and M71 stay dormant

**Files:**
- Modify: `src/qat/data/broker/ib_translate.py` (`from_ib_trade`), `src/qat/data/broker/ib_adapter.py` (`place_order`)
- Test: `tests/data/broker/test_ib_order_identity.py` (create)

`from_ib_trade` updates status and `filled_price` and nothing else. Alpaca's adapter overwrites `order.order_id` with the broker's id at three sites, which is what lets `_order_the_broker_calls` resolve an incoming fill back to the order that produced it.

- [ ] **Step 1: Write the failing test** — an order placed through the adapter, then a `Trade` or `Fill` carrying IBKR's own id, must resolve back to that order. Assert the resolution, not the field.
- [ ] **Step 2: Prove it red.**
- [ ] **Step 3: Implement.** Prefer `permId` if Task 1 showed it stable across a restart; `orderId` is per-session on IBKR, and a per-session id written into a record that outlives the session is a defect waiting to happen. **State which you chose and why.**
- [ ] **Step 4: Prove M70 and M71 actually wake up.** A test that an announced price differing from the fill produces a correction *through the IBKR path*. This is the acceptance test for the whole task — without it you have written a field, not a fix.
- [ ] **Step 5: Green, four checks, commit.**

**Files:**
- Modify: `src/qat/data/broker/ib_adapter.py`, `src/qat/data/broker/ib_translate.py`

Both come from `openTrades()`. `resting_stops` is symbol to stop price; `resting_stop_orders` returns the richer record — read the protocol for the exact shape.

**Why it matters:** without it the app stops verifying that what it believes protects the book is actually resting at the broker. Ten positions "carrying a stop" becomes an assertion rather than an observation, and that was the US trial's single strongest safety claim.

- [ ] Standard TDD cycle against a fake `IB`, then the four checks, then commit.

### Task 5: `announcements` — decide, do not implement blind

**No IBKR equivalent exists.** This task's deliverable is a recorded decision, not code.

The options, with what each costs:

1. **Accept the gap and make it loud.** M39's monitor already reports blindness as a STATE rather than a silence (12 August). Extend that: on an adapter without `announcements`, the Risk Console says corporate-action detection is UNAVAILABLE rather than "none pending". Cheapest and honest, and it leaves the ex-date gate — the piece observed working in production — with no input.
2. **Source announcements elsewhere.** ASX company announcements are published by the exchange, so a separate feed could supply them. Real work, and it belongs with Stage 2's market-data decision.
3. **Drop corporate-action detection for the ASX phase.** Defensible only against the MNST loss on the record: an unadjusted stop through a split cost −51.4% on a position that should have been roughly flat.

- [ ] **Write the decision up with its cost and commit it.** Do not implement any option before the operator has chosen.

## Stages 2 to 4, outlined only

**Stage 2 — market data.** Which vendor supplies ASX daily bars, corporate-action adjusted, with point-in-time membership including delisted names. The spec notes this is commercially available for the ASX in a way US index membership is not, so **the survivorship caveat every research manifest currently carries could actually be removed** — an argument for the move that has nothing to do with the strategy.

**Stage 3 — ASX trading rules.** The **$500 minimum marketable parcel** reaches position sizing directly and is implemented nowhere. Also tick sizes, T+2 settlement against cash reconciliation, and the opening and closing auctions against session logic written for a 13:30 UTC open.

**Stage 4 — regime re-sourcing.** All five macro series are US, and the two carrying most of the signal have no FRED-hosted Australian equivalent. **Do not start this until the ablation question is settled** — the 19 August run found every rail inside noise, so whether the regime gate earns its keep at all is open, and if it does not, this stage disappears entirely.

## What this plan deliberately does NOT do

- **No live trading.** Paper only, and the port guard stays as it is.
- **No order placed on IBKR until Task 1 has reported.**
- **No M84/M85 activation**, no strategy parameter changes, no Kelly changes.
- **No rebuild of M43 in the Alpaca shape** — ASX halts are announcement-driven, so its shape depends on Task 5's decision.
