# Revised 27/28 October OCA paper probe — offline build for review

This isolated script is an experiment for G2, not production exit support or evidence of continuous broker protection. No run is scheduled or authorised by this build. DS must approve the reviewed commit and the exact private approval-file SHA-256 separately. No QAT application, AI, OMS or live account is involved.

## Fixed scope and start conditions

`scripts/phase1_oca_exit_handoff_paper_probe.py` is date-gated to the session named in the new signed approval: 27 October 2026, 14:00 inclusive to 15:30 exclusive, or 28 October 2026, 11:30 inclusive to 15:30 exclusive Australia/Sydney. No new order or cancel is sent at or after 15:30. Start once, with a flat approved paper account and no working orders, localhost Gateway 4002, order client 1 and independent read-only client 99. The exact DS-specified account is pinned by its SHA-256 in the script and supplied only in the private approval. Every wire request rechecks that it is the sole managed account. Client 99 cannot place, cancel or bind orders. Do not start another client using either ID.

Use a separate private directory named `phase1-oca-exit-handoff-YYYYMMDD` for that approved session, outside every Git working copy. DS supplies `approval.json`; the script never creates or signs it. Its seven exact fields are account, approved_by `DS`, approval_date equal to the actual signing date, session `2026-10-27` or `2026-10-28`, symbol `BHP.AX`, operator `DS`, cap_per_order_aud `800`. A separately approved exact SHA-256 is mandatory. A new revision/session lock `oca-revised-YYYYMMDD-attempt.lock` is claimed before connecting; never remove it to retry. The morning 27 October lock remains untouched. This build accepts a new file signed 27 October for either session, or signed 28 October for 28 October; the old 26 October approval is refused. The exact approved hash binds DS's signing-date assertion; the script neither creates/signs a file nor independently proves when DS signed it. The build does not provide a signed file, digest or launch instruction.

A live snapshot with usable bid/ask keeps the live reference. The preserved 27 October attempt supplies delayed type 3 reqTickers snapshot evidence, but its live snapshot was unusable. Delayed reception is not proof of live quote entitlement. If the initial snapshot has no usable bid/ask, request market data type 3 once on client 99 and retry a snapshot. Record the requested type, actual returned type and raw response, including unavailable responses. Only actual type 1 or explicitly selected type 3 is usable; types 2/4 and unknown types are refused. An initially returned type 3 must go through explicit fallback selection and receives the buffer. Never resend the type request. If delayed bid/ask is still unavailable, do not place an entry. The receipt timestamp remains subject to the existing check; it is not a claim that delayed prices are live.

After selecting delayed data, set the entry limit to reference x 1.01 rounded up to the ASX tick, including a tick-band crossing. Size and apply the A$800 buy cap using that actual limit price. Protective stop/target reference rules and market-exit rules remain unchanged. The private 27 October evidence records that fallback; it does not establish live quote availability or an OCA handoff outcome.

A minimum A$500 reference parcel, rounded up to whole shares with at least two shares, follows the existing local paper-probe convention. Every order is checked against A$800. A limit buy is bounded by its limit price. Protective and cleanup market orders use the observed IBKR ask as the sizing reference; a market fill cannot guarantee an A$800 realised value. This limitation must remain in the auditor/DS approval, rather than being described as a guaranteed execution cap. Bid, ask, reception timestamp and market-data type are recorded. No other data source is used.

## Experiment, types 2, 3, then 1

For each type, confirm a flat book with no working orders, buy the minimum parcel, then place a SELL stop and target in a single fresh OCA group. Confirm both working before submitting an approximately half-parcel market SELL in that same group. The initial acquisition-to-protection interval is recorded too; the script does not claim the initial buy is continuously protected.

Client 99 polls positions and all open orders about once per second. Every snapshot records the holding, stop status, remaining stop quantity, group/type, order identities and raw position/order evidence. Gaps in poll coverage are recorded. A stop counts as protection only if it is a working SELL stop in the pinned group with unchanged stop terms and exactly the remaining holding. Broker OCA quantity reductions are allowed. Action and order type are pinned. Group/type are compared only for orders the script placed in a group (stop, target, joined SELLs); the ungrouped LMT entry compares only action, orderType and lmtPrice. IBKR returns ocaType3 on ungrouped orders; that default is not a group membership. Only auxPrice for STP and lmtPrice for LMT are compared, using Decimal prices rounded to the nearest ASX tick. Unused prices are ignored regardless of their wire/default value.

An owned PreSubmitted/Submitted order with zero remaining quantity in a client-99 response is incomplete evidence for that entire poll. Record and retry next poll; do not claim protection, open/close a protection gap or send a cleanup sale on that response. Safety checks on identities, account and other observed oversell risks still apply. Action callers wait for a usable snapshot, within the existing session deadline; no stale snapshot substitutes for it.

If protection disappears after confirmation but before the half sale (including during the quote request), skip the half sale and clean up the full independently observed holding. After the half sale, an exact remaining stop leads to a second same-group handoff for the balance. A missing or undersized stop leads immediately to market cleanup using the last IBKR reference, without waiting for execution-detail requests or restoring a stop. The unprotected interval is a finding. If a market exit itself partially fills while protection disappears, cancel its unfilled remainder once and wait until terminal before submitting cleanup; never create two independently executable exit sales. If any working SELL exceeds the holding, oversell safety takes precedence and no further order is sent.

The normal protected handoff path preserves its existing ordering. On any non-transmission halt, emergency cleanup instead cancels every owned working order once, including protective legs, and waits until all owned buys/SELLs are terminal before a single ungrouped market sale of the freshly observed holding. No stop is placed or restored. This emergency path is not evidence of a protected production handoff. Dispatch each necessary cancel once before waiting; PendingCancel, including an unsolicited PendingCancel, is waited through without resending. Inactive is also waited through. Waits are bounded by 15:30 and may last more than 20 minutes. An unresolved order stops the experiment and requires DS action. The next type requires independent flat/no-working-order confirmation.

## Halts, evidence and interpretation

Transmission halts are exact-account failure, unrelated position/order or order identity, and any oversell risk (including ambiguous order acknowledgement). They forbid further orders or cancels. Every other halt, including changed terms, uses emergency cleanup with fresh account, ownership, position and order checks. A background terms halt is latched for the main path but does not disable its own cleanup. After a halt the remaining OCA types are not started. A failed observation is not proof of broker rejection or of a protection gap.

The script does not disconnect while a known own order is non-terminal before 15:30. It observes terminal states and fresh client99 books, including after a transmission halt, without sending forbidden cancels. Failed account/evidence checks cannot be bypassed; they are recorded and observation continues to the deadline. At 15:30 unresolved orders are named with the held quantity as DS action required. No sale starts at/after15:30. Final flatness requires zero holdings and no working orders in one client99 snapshot, all known orders terminal, and reconciliation to attributable owned fills; an earlier zero-position response alongside a pending entry cannot qualify.

The final independent client-99 inventory is attempted after both completion and a halt; it never transmits. Unknown or invalid holdings are reported as unavailable, never truncated or inferred from an earlier snapshot. Any held shares, working orders, unavailable final inventory or halt produces **DS action required**, with the independently observed held quantity or explicitly unavailable quantity.

Private raw JSON includes every client-99 snapshot, protection intervals, SDK errors/status/fill/commission events, requested orders and cancels, reqExecutions evidence and completed orders, final inventory and its timestamp. The final report prints its path and SHA-256. Keep all raw evidence and account identifiers outside Git. Review acceptance/joining for every OCA type, stop quantity after every fill, both handoffs, all cancel states and final flat state.

One-second sampling cannot prove uninterrupted protection between polls. Absence of an observed oversell does not prove IBKR blocks overfill; type-specific observations and any unanswered question must be reported explicitly. This probe deliberately tests partial exits; it does not deliberately create an oversell race to manufacture a blocking result. G2 remains open unless the broker evidence supports its full acceptance criteria.

## Offline validation

Tests use real ib_async objects behind a fake broker and clock. Every reqAllOpenOrdersAsync response builds independent Order/Contract wire fields, runs the installed Decoder.parse and wrapper.openOrder, and applies wrapper.orderStatus only when that status evidence is present. No response returns the script's own Trade/Order/OrderStatus. Every scenario runs under both unused-price wire "0" and empty/UNSET_DOUBLE variants. Extra cases cover float drift, missing working remaining quantity, next-poll recovery, one delayed-type request, unusable snapshots and buffered limit tick/cap boundaries. They cover type order and half/full exits, type-1 stop cancellation, disappearing and oversized stops, delayed cancels, unrelated exposure, holding changes during a quote, ambiguous acknowledgements, changed protective terms, prompt gap cleanup, intermediate partial fills, independent final inventory and invalid final quantities. No Gateway connection or order-capable script execution occurs during tests.

## Revised regressions

The distilled 26 October B completed-order fixture contains observed non-account wire defaults, including ungrouped ocaType3. Independent Decoder/wrapper objects replay these defaults under both zero and UNSET unused-price variants. New scenarios include a PendingSubmit entry while positions read zero; a used-price mismatch cancelled once and waited through 20 minutes without a sale; a fill racing the mismatch followed by one ungrouped market cleanup and no stop; transmission halts with no further orders; unresolved own orders at15:30 with zero position still requiring DS action; stale zero-position replies after confirmed fills; both session windows, signing dates and separate locks. No raw account identifiers or broker evidence files are committed.

Independent final review regressions also refuse flatness after an incomplete positions/orders pair, forbid cancellations on a zero-holding executable-SELL risk, resume cleanup after a transient read failure, report foreign exposure promptly once own orders settle, and reject false-flat intermediate messages after a partially filled terminal emergency sale. Such a residual is handed to DS; no second emergency sale is sent.

The last independent snapshot is also subject to the terminal-order drain: an earlier terminal check never authorises disconnect if the final client99 book newly shows an own non-terminal order. It is observed read-only until settlement or the window end, and final flatness is then evaluated on the refreshed complete book.
