# Private authority continuity: build and operator gates

This branch implements the DS-adopted 2 November design. It does not apply recovery or change existing evidence. All approved base files and historical records remain byte-identical. A new catch-up record is explicit retrospective evidence, not a backdated daily audit or permission to replay missed shadows.

The private catch-up approval has exactly: schema, approved_by, signing_date, first_session, last_session, authority_hashes, audit_sha256, membership_successor_sha256, expected_tip_sequence, expected_tip_content_hash. The schema is qat-authority-catchup-approval-v1. DS creates/signs the real file and approves its exact SHA-256 independently. Dates satisfy last_session <= signing_date <= recorded_at's Sydney date. No signed_at, root or ledger-prefix hash fields are accepted.

The restriction file has exactly: schema, base_membership_file_sha256, approved_by, signing_date, restrictions, evidence_sha256s. Schema asx-membership-restriction-v1 supports the interim MFG-only restriction: last active 30 October 2026, effective 2 November 2026. Each restriction has symbol, last_active_session, effective_from, reason, source_sha256s. All other members remain unchanged; no BJY entry or identity mapping is possible.

Configuration pins: phase3_catchup_approval_file/sha256, phase3_membership_successor_file/sha256, and phase3_catchup_audit_file for writes and independent verification. Matching CLI flags are --catchup-approval-file/sha256, --membership-successor-file/sha256 and --catchup-audit-file. These do not replace the four existing DS-approved authority hashes. Missing or changed required evidence refuses; source selection cannot fall back to retired MFG. The review manifest is not parsed; its SHA-256 is checked at dry-run, apply and independent verification. Ordinary reads recheck approval/successor only.

Catch-up writer: scripts/attest_phase3_authorities_catchup.py uses --first-session, --last-session, --operational-root, --authorities-dir, --audit-file/sha256, four authority hash flags and independently pinned continuity arguments. Default is dry-run; --apply is the sole write opt-in. Clock is actual current Sydney time; no backdating flag. Its default dry-run and apply share validation. One exclusive writer lock protects a single fsynced line and a fresh reader verifies afterward. A preexisting lock or uncertain/partial outcome stops; no automatic retry, truncation or repair.

Daily writer: scripts/attest_phase3_authorities.py retains --session and current-session audit arguments, plus continuity evidence pins and the range audit path. It validates a normal next-session line after the range. Both writers require an existing correctly labelled OPERATIONAL namespace; neither opens the bar database for mutation.

Shadow: scripts/phase3_shadow_readonly_check.py performs exactly one pass. It resolves the active set once before its account request, passes the same immutable selection through fetch/freeze/eligibility, and freezes its fingerprint. Its historical raw-only mode now records an abstention without data requests. Both this entry point and Phase3ShadowRunner use independently approved file hashes and the ledger-bound successor. Managed historical data never broadens new-card membership.

The committed shadow/source 20:00 gate is unchanged. A task's 23:00 outer policy cannot override it. No new start-window extension is implemented by this branch. Audit/shadow tasks require separately confirmed new pins before reading a catch_up_v1 record; old pins reject its schema. No task update, actual append or probe is authorised by this document. Temporary-fixture tests cover full recovery/preservation and later daily advancement.
